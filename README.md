# LLM Data Poisoning Thesis Experiments

**Read the full thesis paper here:** [Data Poisoning Attacks on Large Language Models](https://drive.google.com/file/d/1PCXvMZh9RuvCL-OJm6RQZoBFNi2qB-HV/view?usp=sharing)


This repository contains the source code, training loops, evaluation metrics, and analytical plots for a thesis experiment investigating data poisoning attacks on Large Language Models (LLMs). The experiments compare vulnerabilities across different domains (General/Eiffel vs. Astronomy) and architectures (Qwen vs. Mistral).

## Prerequisites (Installing Conda)
To run these experiments, you will need the `conda` package manager installed. If you do not have it, follow these steps:
1. Download Miniconda:
   ```bash
   wget https://repo.anaconda.com/miniconda/Miniconda3-latest-Linux-x86_64.sh
   ```
2. Run the installer:
   ```bash
   bash Miniconda3-latest-Linux-x86_64.sh
   ```
3. Follow the prompts, restart your terminal, and verify the installation:
   ```bash
   conda --version
   ```

## Environment Setup
Recreate the exact reproducible Conda environment using the provided `environment.yml` file:
```bash
conda env create -f environment.yml
conda activate llm-poison-env
```

## Repository Structure & File Definitions

### Root Directory
*   `analyze_experiments.py`: Generates the aggregate analysis dashboard plot (`poisoning_analysis_dashboard.png`) by compiling the JSON evaluation logs from all four experiment conditions.
*   `visualize_human_metrics.py`: Reads the anonymized `data.csv` survey results and generates the human validation plots (`human_validation_plots.png`).
*   `environment.yml`: The Conda environment export for strict reproducibility.

### Experiment Subdirectories
There are four experiment directories representing the variations in the experiment: `poison-experiment`, `poison-experiment-astronomy`, `poison-experiment-astronomy-llama`, and `poison-experiment-llama`.

Inside each directory, you will find:
*   `train_loop.py`: The core training script. It loads the base LLM, injects the poisoned data, fine-tunes the model across multiple cycles, and caches the checkpoints.
*   `train_loop_control.py`: The exact same architecture as `train_loop.py`, but it trains strictly on the benign control dataset to establish a baseline.
*   `probe.py`: The evaluation script. It loads the trained checkpoints (both poisoned and control) and evaluates them against the testing benchmarks (e.g., TruthfulQA). Outputs are saved to the log directories.
*   `setup_datasets.py`: Utility script used by the training loops to handle tokenization and structured dataset loading.
*   `generate_human_samples.py`: Generates specific formatted model outputs to be evaluated by human annotators in a blind survey.
*   `data.csv`: The raw results of the human validation survey. *(Note: Email addresses have been masked to protect PII)*.
*   `master_key.csv`: The key mapping annotator questions to expected answers.
*   `data/`: Contains the specific JSON and Arrow formats of the training subsets (benign and poisoned) and evaluation sets.
*   `logs_reprobe/` & `logs_control_reprobe/`: JSON output directories containing the metric results generated by `probe.py`.

*(Note: Massive trained model weights and intermediate tensor caches have been excluded from this repository to adhere to file size limits. They can be re-generated by running the training loops).*

## Pipeline Execution Order
To reproduce the experiment for a specific condition, navigate to its directory (e.g., `cd poison-experiment-astronomy`) and run the pipeline:

1. **Train Poisoned Model:** `python train_loop.py`
2. **Train Control Model:** `python train_loop_control.py`
3. **Evaluate (Probe):** `python probe.py`
4. **Analysis:** Navigate back to the root directory and run `python analyze_experiments.py` to plot the results.
